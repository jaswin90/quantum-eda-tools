Statistical learning for design and manufacturing

Goals

  • Understand what a surrogate model is and why expensive simulations need one.
  • Build Gaussian-process regression from scratch, with its uncertainty, and use it for Bayesian optimisation.
  • Build hierarchical models for nested manufacturing data, such as predicting cold qubit frequencies from warm measurements.
  • Check whether a model's error bars are honest (calibration, conformal prediction, distribution shift).
  • Choose experiments to learn as much as possible (design of experiments, Bayesian experimental design, simulation-based inference).

Every open problem in the review needs statistics. Simulations are too slow to run thousands of times, so we need fast surrogates that also say how uncertain they are. Manufacturing data comes in nested groups (junctions on dies on wafers on lots), so we need models that share information across groups. Cold test time is scarce, so we need to choose measurements wisely. And we need to know when to trust a model's predictions. This chapter introduces the core tools, assuming only the probability of Book 1 Chapter 7. For each, it explains the idea in plain words, the key formula, a worked example, and where it fits in quantum design.

Why surrogates

An electromagnetic simulation of one qubit cell takes minutes to hours (Chapter 3). An optimiser exploring designs, or a Monte Carlo estimating yield (Chapter 4), may need thousands to millions of evaluations. A surrogate is a cheap model of the expensive map \(\mathbf x\mapsto y\) (for example, pad geometry → capacitance → frequency), fitted to a modest number of simulations. A good surrogate does two things: predicts \(y\) at new \(\mathbf x\), and says how sure it is, so that we know when to fall back on the real simulator.

Gaussian processes

A Gaussian process (GP) is a way to put a probability distribution over functions. Its defining property: for any finite set of inputs, the function values are jointly Gaussian (@b1:sec-m-prob-dists), with a covariance given by a kernel \(k(\mathbf x,\mathbf x')\). The kernel encodes what we believe about the function before seeing data. The most common, the squared-exponential kernel

\[ k(\mathbf x,\mathbf x') = \sigma_f^2\exp\Big(-\frac{\|\mathbf x - \mathbf x'\|^2}{2\ell^2}\Big), \]

says: "nearby inputs give similar outputs; similarity fades over a length scale \(\ell\); typical output variation is \(\sigma_f\)". It describes smooth functions, which suits the smooth dependence of frequencies and couplings on geometry [@rasmussen2006].

Given noisy observations \(\mathbf y\) at inputs \(X\) (noise variance \(\sigma_n^2\)), Bayes' rule (@b1:eq-m-bayes) gives the prediction at a new input \(\mathbf x_*\) as a Gaussian with

$$ \mu_* = \mathbf k_*^{\mathsf T}(K + \sigma_n^2I)^{-1}\mathbf y, \qquad \sigma_*^2 = k(\mathbf x_*,\mathbf x_*) - \mathbf k_*^{\mathsf T}(K+\sigma_n^2I)^{-1}\mathbf k_*, $$

where \(K_{ij} = k(\mathbf x_i,\mathbf x_j)\) is the kernel between all pairs of training points and \((\mathbf k_*)_i = k(\mathbf x_i,\mathbf x_*)\) between the training points and the new one.

Read the mean as a weighted average of the observed values, with weights that are large for training points close to \(\mathbf x_*\) (via \(\mathbf k_*\)) and adjusted so that nearby training points do not double-count (via \(K^{-1}\)). Read the variance as "prior uncertainty minus what the data explain": near data, the subtracted term is large and the uncertainty small; far from data, \(\mathbf k_*\to0\) and the uncertainty returns to the prior \(\sigma_f^2\). The GP knows where it has not looked (@fig:f-gp).

The kernel's hyperparameters (\(\ell\), \(\sigma_f\), \(\sigma_n\)) are chosen by maximising the marginal likelihood, the probability of the observed data under the model, which automatically balances fit against complexity. GPs work very well for smooth functions of up to tens of inputs with hundreds to a few thousand training points (the cost is dominated by inverting the \(n\times n\) matrix, \(O(n^3)\)). For larger problems, neural-network surrogates and operator-learning models, which map whole geometries or fields to fields, take over [@li2021fno; @lu2021deeponet].

Worked example: one data point. One observation \(y_1\) at \(x_1\), kernel variance \(\sigma_f^2 = 1\), noise \(\sigma_n^2 = 0.01\). At \(x_* = x_1\): \(\mu_* = \frac{1}{1.01}y_1\approx0.99y_1\) and \(\sigma_*^2 = 1 - \frac{1}{1.01}\approx0.0099\): the prediction trusts the data and the uncertainty is about the noise level. Far away (\(k_*\to0\)): \(\mu_*\to0\) (the prior mean) and \(\sigma_*^2\to1\): no information. In between, the length scale \(\ell\) decides how quickly knowledge fades.

Try it: a Gaussian process in fifteen lines

Nothing about @eq:f-gp needs a library. The code below implements it directly with NumPy for a one-dimensional example, so you can see every step. Change the length scale ell and watch the uncertainty band change: a short length scale says "the function could wiggle between data points"; a long one says "it is smooth".

import numpy as np

def kernel(a, b, sf=1.0, ell=0.45):
    return sf**2 * np.exp(-(a[:, None] - b[None, :])**2 / (2 * ell**2))

x = np.array([-1.6, -0.9, -0.4, 0.3, 0.8, 1.1])        # where we ran the simulator
y = np.sin(3 * x) + 0.3 * x                              # what it returned
sn = 0.05                                                # simulator noise (std)

K = kernel(x, x) + sn**2 * np.eye(len(x))
xs = np.linspace(-2.5, 2.5, 200)                         # where we want predictions
Ks = kernel(x, xs)
mu = Ks.T @ np.linalg.solve(K, y)                        # posterior mean
var = 1.0 - np.sum(Ks * np.linalg.solve(K, Ks), axis=0)  # posterior variance
sd = np.sqrt(np.maximum(var, 0))
print(xs[::40], mu[::40].round(2), sd[::40].round(2))

This is the code that produced @fig:f-gp. In real use, solve with a Cholesky factorisation for stability, fit ell, sf and sn by maximising the marginal likelihood, and use a library (scikit-learn, GPyTorch) once you understand what it does.

Bayesian optimisation

To find the design that minimises an expensive function (say, the error of a gate as a function of pad geometry), Bayesian optimisation repeats:

  1. Fit a GP to all evaluations so far.
  2. Choose the next point by maximising an acquisition function that balances exploitation (low predicted mean: probably good) and exploration (high uncertainty: might be better). The popular expected improvement is \(\mathbb E[\max(0, y_{\mathrm{best}} - f(\mathbf x))]\) under the GP posterior, which has a closed form.
  3. Run the expensive simulation there, and repeat.

It typically finds good optima of smooth functions in tens to hundreds of evaluations [@frazier2018], and has been used to discover superconducting circuit designs automatically [@menke2021]. Multi-fidelity variants combine cheap approximate simulations (coarse meshes, lumped models) with a few expensive accurate ones.

Hierarchical models

Manufacturing data are nested: junctions within dies, dies within wafers, wafers within lots. Treating every junction as independent ignores that junctions on the same wafer share a wafer offset; treating each wafer separately wastes what other wafers teach. A hierarchical model [@gelman2013] gives each level its own random effect drawn from a population:

$$ y_{ijk}\sim\mathcal N\big(\boldsymbol\beta^{\mathsf T}\mathbf z_{ijk} + u_j + v_{jk},\ \sigma^2\big), \qquad u_j\sim\mathcal N(0,\tau_w^2), \qquad v_{jk}\sim\mathcal N(0,\tau_d^2) . $$

Here \(y_{ijk}\) could be the measured cold frequency of junction \(i\) on die \(k\) of wafer \(j\); \(\mathbf z_{ijk}\) are covariates (warm resistance, junction area, position on the wafer) with coefficients \(\boldsymbol\beta\) from physics (Ambegaokar–Baratoff and the transmon formula); \(u_j\) is wafer \(j\)'s offset, \(v_{jk}\) die \(k\)'s offset, and \(\sigma\) the remaining junction-level scatter. Fitting the model (by Markov-chain Monte Carlo or variational inference) gives posterior distributions for all of these.

The key behaviour is partial pooling. Before any cold measurement on a new wafer, its offset \(u_j\) is predicted to be zero ± \(\tau_w\) (the spread seen across previous wafers). Each cold measurement on that wafer pulls the estimate towards what that wafer actually does. With few measurements, the estimate leans on the population; with many, on the wafer's own data. The model automatically decides how much to trust each.

Worked example: how many cold measurements per wafer? Wafer offsets spread by \(\tau_w = 40\) MHz; junction-level scatter is \(\sigma = 25\) MHz. After measuring \(n\) qubits on a new wafer, the uncertainty in its offset is \(\big(1/\tau_w^2 + n/\sigma^2\big)^{-1/2}\) (normal–normal updating): \(n = 1\): 21 MHz; \(n = 4\): 12 MHz; \(n = 16\): 6 MHz. A handful of cold measurements per wafer pins down its offset and sharpens predictions for every other die on it. This is the structure of the review's warm-to-cold model (@lf:eq-hier).

Are the error bars honest?

A model's uncertainty is only useful if it is calibrated: of all the 90% prediction intervals it gives, about 90% should contain the truth. Check this on data the model did not see. If 90% intervals contain the truth only 60% of the time, the model is overconfident and dangerous for sign-off.

Conformal prediction [@angelopoulos2023] repairs calibration for any model. Take a calibration set the model was not trained on, compute the absolute errors, and find their \((1-\alpha)\) quantile \(q\) (with a small finite-sample correction). Then "prediction ± \(q\)" contains the truth with probability at least \(1-\alpha\) on new data, guaranteed, whatever the model. The guarantee requires one assumption: new data must be exchangeable with the calibration data (drawn from the same distribution).

The most dangerous failure of a learned model is not inaccuracy on familiar inputs; it is confident wrong answers on unfamiliar ones. A surrogate trained on transmons with 20 µm gaps may be excellent there and silently wrong for 5 µm gaps, or for a new foundry's process. This is distribution shift, and it breaks conformal guarantees too. Detect it by checking whether new inputs resemble the training set and whether residuals drift over time. The review's rule follows: a surrogate may propose designs, but must not approve them unless its error is bounded on the designs actually submitted (@lf:sec-design-inverse).

Choosing experiments

When each measurement is expensive (an hour of fridge time, a wafer run), choose them to be informative.

  • Classical design of experiments [@montgomery2012] varies process factors (oxidation pressure, time, temperature) systematically, in factorial or response-surface patterns, to fit a model with the fewest runs and separate the effects of each factor.
  • Bayesian experimental design chooses the next experiment \(\xi\) to maximise the expected information gain about the unknown parameters \(\theta\): \(\mathrm{EIG}(\xi) = \mathbb E_{y|\xi}\big[\mathrm{KL}(p(\theta|y,\xi)\,\|\,p(\theta))\big]\), the expected reduction in uncertainty (@lf:eq-boed). In plain words: measure where the outcome is most uncertain and most informative about what you care about. Adaptive versions already speed up qubit characterisation, for example choosing Ramsey delays or spectroscopy frequencies on the fly.
  • Simulation-based inference [@cranmer2020] fits models whose likelihood cannot be written down but which can be simulated (a noisy device model, say): neural networks are trained on simulated data to approximate the posterior, which suits inferring noise models from benchmark data.

Every one of the review's seven open problems uses something from this chapter: chance-constrained optimisation (Problem 1), surrogates with certified error (Problem 2), hierarchical warm-to-cold models (Problem 4), Bayesian experimental design for test (Problem 5), and simulation-based inference for error models (Problem 6). The methods exist; what is missing is their careful application to quantum devices with real production data (@lf:sec-prob-ml).

  • Surrogates replace slow simulators and must report uncertainty.
  • Gaussian processes: the mean interpolates data, the variance grows away from data; the kernel encodes smoothness.
  • Bayesian optimisation balances exploration and exploitation to optimise expensive functions in few evaluations.
  • Hierarchical models share information across wafers and dies (partial pooling); a few cold measurements per wafer go a long way.
  • Check calibration; conformal prediction guarantees coverage only without distribution shift; surrogates propose, accurate solvers approve.
  • Choose experiments for expected information gain; use simulation-based inference when only a simulator is available.

Exercises

  1. For a GP with one observation \(y_1\) at \(x_1\), noise \(\sigma_n\) and kernel variance \(\sigma_f^2\), write \(\mu_*\) and \(\sigma_*^2\) at \(x_* = x_1\) and far from \(x_1\).
    Solution

    At \(x_1\): \(\mu_* = \frac{\sigma_f^2}{\sigma_f^2+\sigma_n^2}y_1\), \(\sigma_*^2 = \frac{\sigma_f^2\sigma_n^2}{\sigma_f^2+\sigma_n^2}\). Far away: \(\mu_*\to0\), \(\sigma_*^2\to\sigma_f^2\).

  2. With \(\tau_w = 40\) MHz and \(\sigma = 25\) MHz, after how many cold measurements on a wafer is its offset known to within 5 MHz (one standard deviation)?
    Solution

    Need \(1/(1/1600 + n/625)\le25\), i.e. \(1/1600 + n/625\ge0.04\), \(n\ge625\times(0.04 - 0.000625) = 24.6\): 25 measurements.

  3. A conformal calibration set has 200 residuals and you want 90% intervals. Which residual defines the interval half-width?
    Solution

    The \(\lceil(n+1)(1-\alpha)\rceil = \lceil201\times0.9\rceil = 181\)st smallest absolute residual.

  4. A surrogate's 90% intervals on a held-out test set contain the truth only 70% of the time. What does that tell you, and what would you do?
    Solution

    The model is overconfident (its uncertainties are too small). Recalibrate (for example with conformal prediction on a calibration set), check for distribution shift between training and test data, and do not use it to approve designs until coverage is restored.

  5. In Bayesian optimisation, why would a pure "go to the lowest predicted mean" rule get stuck?
    Solution

    It never samples uncertain regions, so it can never discover that an unexplored region is better; it keeps refining around the first decent point it found. The exploration term (uncertainty) in the acquisition function is what lets it escape local optima.
