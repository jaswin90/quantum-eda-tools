Quantum error correction II: the surface code and fault tolerance

Goals

  • Draw the surface code, and identify its stabilisers, logical operators and distance.
  • Follow one error-correction cycle on hardware and understand detection events in space and time.
  • Understand what a decoder does, why it must be fast, and what a detector error model is.
  • Derive the threshold scaling law, define the suppression factor \(\Lambda\), and compute qubit overheads from it.
  • See how logic is done on encoded qubits (lattice surgery, magic states) and where qLDPC codes fit.

The surface code is the error-correcting code that most hardware companies are building towards, because it only needs each qubit to talk to its four nearest neighbours on a flat grid, which is exactly what a chip can provide. Physical qubits are laid out in a square patch; helper qubits between them repeatedly measure four-qubit parity checks; a fast classical computer (the decoder) reads the stream of check results and works out which errors happened. Below an error rate of about 1%, making the patch bigger makes the stored logical qubit exponentially more reliable. The factor by which it improves with each size step, \(\Lambda\), is the single most important number for a quantum processor, and it is the number the review this course prepares for is built around.

The layout

Arrange \(d\times d\) data qubits on the corners of a square grid (with \(d\) odd: 3, 5, 7, ...). Each little square face of the grid touches four data qubits. Colour the faces like a chessboard. On each dark face, place an ancilla that measures the \(Z\)-type check \(Z\!Z\!Z\!Z\) on its four data qubits; on each light face, an ancilla that measures the \(X\)-type check \(X\!X\!X\!X\). Along the boundaries, add half-faces with two-qubit checks so that the patch is complete. This is the rotated surface code [@dennis2002; @fowler2012].

  • Do the checks commute? They must, to be stabilisers (Chapter 6). A \(Z\)-check and an \(X\)-check on neighbouring faces share an edge, i.e. two data qubits. Two overlaps mean two sign changes, so they commute. Same-type checks commute trivially.
  • How many qubits? \(d^2\) data qubits and \(d^2-1\) checks, so \(2d^2-1\) physical qubits store one logical qubit: \([[d^2, 1, d]]\). Distance 3 uses 17 qubits; distance 7 uses 97; distance 25 uses 1,249.
  • Logical operators. A line of \(Z\)s running across the patch from one boundary to the opposite one commutes with every \(X\)-check (it crosses each one on an edge, two qubits) and is not a product of \(Z\)-checks: it is \(\bar Z\). A line of \(X\)s in the perpendicular direction is \(\bar X\). Both have length \(d\), so the distance is \(d\).

Why does a bigger patch protect better? An error only becomes a logical error if it forms an unbroken chain across the whole patch, at least \(d\) qubits long. Short error chains are detected at their ends (the checks there flip) and corrected. Making the patch larger makes the shortest dangerous chain longer, and long chains of independent errors are exponentially unlikely.

The surface code's attractions are engineering ones. Every check involves only four nearest neighbours on a planar grid, so the chip needs only short couplers in two dimensions; each qubit couples to at most four others; and the threshold is high, around 1% for realistic circuit noise. Its drawback is overhead: hundreds to thousands of physical qubits per logical qubit at useful distances.

One error-correction cycle on hardware

One QEC cycle measures every check once. On a superconducting chip it goes:

  1. Reset all ancillas to \(\ket0\).
  2. Hadamard on the \(X\)-check ancillas (so they measure \(X\)-parities, by the Hadamard sandwich of Chapter 1).
  3. Four rounds of two-qubit gates, each ancilla interacting with its four data qubits one at a time. The order of the four is chosen carefully so that a single fault in the middle of a check cannot produce an error chain that shortens the distance ("hook errors").
  4. Hadamards again on the \(X\)-check ancillas.
  5. Measure all ancillas.

On current hardware a cycle takes about a microsecond, dominated by measurement and reset. The cycle repeats continuously for as long as the logical qubit is stored.

Detection events. Measurements themselves are sometimes wrong, so one cycle's results cannot be trusted alone. Instead we compare each check's result with its result in the previous cycle. If it changed, that is a detection event. Now look at what each kind of fault produces:

  • A data-qubit error between cycles flips the (one or two) checks that touch that qubit: detection events in space, at the two ends of the error.
  • A wrong measurement in cycle \(t\) differs from cycle \(t-1\) and from cycle \(t+1\), when the correct value returns: two detection events in time on the same check.

So every fault is an edge with detection events at its endpoints, in a three-dimensional space-time lattice (two dimensions of chip, one of time). Chains of faults have events only at their two ends. The decoder sees only the events and must guess the chains.

Decoders

The decoder takes the detection events and decides which correction to apply. It does not need to identify the exact errors, only whether the most likely set of errors includes a logical operator (crosses the patch) or not. For independent errors, the most likely explanation is the one with the fewest faults: pair up the detection events with the shortest total chain length. That is minimum-weight perfect matching (MWPM), solved efficiently by Edmonds' blossom algorithm; modern implementations handle thousands of qubits in real time. Union-find decoders are faster and slightly less accurate; neural-network decoders trained on real device data can be more accurate, because they learn correlated noise that the simple model ignores.

The decoder needs to know how likely each fault is. That information is the detector error model: a list of every possible fault mechanism (each gate's error, each measurement error, each idle period), which detection events it triggers, whether it flips the logical observable, and its probability. It is generated from a noisy circuit description by a Clifford simulator such as Stim (Chapter 6). Its probabilities come from the hardware's measured or predicted error rates, which is where chip design enters.

Real time. Syndromes arrive every microsecond. If the decoder falls behind, the backlog grows without limit, and the machine must stall at every \(T\) gate (which needs decoded results before it can proceed). Real-time decoding for hundreds of logical qubits is a hardware co-design problem: custom chips (FPGAs, ASICs), low-latency links from the refrigerator, and decoder algorithms designed for speed (@lf:sec-qec-dec).

Threshold and the suppression factor \(\Lambda\)

Let each physical fault happen independently with probability \(p\). A distance-\(d\) code fails when a chain of about \((d+1)/2\) faults happens to line up so that the decoder "completes" it the wrong way into a logical operator. The probability of a specific set of \((d+1)/2\) faults is \(p^{(d+1)/2}\); the number of such dangerous sets grows roughly like \(c^{(d+1)/2}\) for some constant \(c\) (chains can wander). Combining, \(p_L\approx A(cp)^{(d+1)/2}\). Writing \(p_{\mathrm{th}} = 1/c\):

$$ p_L(d) \approx A\Big(\frac{p}{p_{\mathrm{th}}}\Big)^{(d+1)/2}, \qquad \Lambda = \frac{p_L(d)}{p_L(d+2)} \approx \frac{p_{\mathrm{th}}}{p} . $$

Read it in two regimes. If \(p \lt p_{\mathrm{th}}\), the bracket is less than one and raising \(d\) shrinks \(p_L\) exponentially: each step \(d\to d+2\) divides it by \(\Lambda\). If \(p > p_{\mathrm{th}}\), the bracket exceeds one and bigger codes are worse, because more qubits means more chances for errors. The crossover \(p_{\mathrm{th}}\) is the threshold, about 1% for the surface code with realistic circuit noise and MWPM decoding (@fig:i-threshold).

Worked example: from \(\Lambda\) to qubit count. A target algorithm needs \(p_L = 10^{-9}\) per logical qubit per cycle. Suppose \(A = 0.1\) and \(\Lambda = 4\) (physical error a quarter of threshold). Then \(0.1\times4^{-(d+1)/2}\le10^{-9}\) requires \((d+1)/2\ge\log_4(10^8) = 13.3\), so \((d+1)/2 = 14\) and \(d = 27\). Each logical qubit costs \(2\times27^2-1 = 1{,}457\) physical qubits. At \(\Lambda = 2\): \((d+1)/2\ge26.6\), \(d = 53\), 5,617 qubits, almost four times more. A modest improvement in physical error rates cuts the machine size by a large factor. Google's Willow processor reported \(\Lambda\approx2.1\) in 2024–25 (@lf:eq-pl); the review shows that raising \(\Lambda\) from about 2 to 4 cuts the physical qubits per logical qubit by more than half.

The threshold theorem assumes faults are independent and local. Correlated errors (a cosmic ray hitting many qubits, leakage that spreads, crosstalk that pairs errors) can create long chains in one event, and they flatten the exponential suppression at low \(p_L\). Showing that a real chip's errors are independent enough for \(\Lambda\) to keep holding at large \(d\) is one of the hardest verification problems in the field, and it is a property of the hardware, not of the code.

Computing on encoded qubits

Storing a logical qubit is not enough; we must compute with it without letting errors spread. A procedure is fault tolerant if a single fault anywhere causes at most a correctable error in each code block. The threshold theorem says that with fault-tolerant procedures and \(p \lt p_{\mathrm{th}}\), computations of any length are possible with an overhead that grows only polylogarithmically with the length.

  • Clifford gates by lattice surgery. Two surface-code patches are placed side by side. Temporarily measuring new checks along their shared boundary merges them, which measures a joint logical operator such as \(\bar Z_1\bar Z_2\); stopping those checks splits them again. Sequences of such joint measurements, with feed-forward, implement CNOT. Each operation takes about \(d\) cycles.
  • The \(T\) gate by magic states. No code has a full universal set of transversal gates, and the surface code cannot do \(T\) directly. Instead, many noisy copies of the "magic state" \(T\ket+\) are prepared and purified by magic-state distillation (15 noisy copies → 1 much better copy, repeated in rounds) [@bravyi2005], then consumed by gate teleportation (@sec:i-ent-tele) to apply \(T\) to a data qubit. Distillation "factories" can occupy a large fraction of a fault-tolerant machine, which is why an algorithm's \(T\)-count dominates its cost.

Beyond the surface code

The surface code stores one logical qubit per patch, so its rate \(k/n\) shrinks towards zero as \(d\) grows. Quantum low-density parity-check (qLDPC) codes store many logical qubits per block at comparable distance. IBM's bivariate bicycle "gross" code \([[144,12,12]]\) stores 12 logical qubits in 288 physical qubits (data plus ancillas), where surface codes of the same distance would need about 3,000 [@bravyi2024]. The price is non-local connectivity: some checks involve qubits that are far apart on a planar layout. That requires long-range couplers or multilayer wiring on a superconducting chip, or physically moving atoms in a neutral-atom array. Bosonic codes (cat and GKP codes) take a different route, storing a qubit in the many levels of one oscillator and combining it with simpler outer codes. The choice of code is therefore inseparable from the choice of hardware layout and fabrication technology (@lf:sec-qec-codes).

The review's Problem 6 asks for an automated pipeline: layout and process statistics → device parameters → gate errors (@lf:eq-eps) → detector error model → decoder → \(p_L\) and \(\Lambda\), including the spread over manufactured chips (@lf:eq-ly). Every arrow in that chain is a model you have now met. Building it with calibrated uncertainty is open research.

  • Rotated surface code: \(d^2\) data + \(d^2-1\) ancillas, alternating four-qubit \(X\) and \(Z\) checks, logical operators are lines across the patch, distance \(d\).
  • Each cycle measures all checks; detection events are changes between cycles; faults are edges in a space-time lattice.
  • Decoders (e.g. minimum-weight matching) pair detection events using a detector error model, and must keep up in real time.
  • Below threshold, \(p_L\approx A(p/p_{\mathrm{th}})^{(d+1)/2}\); \(\Lambda = p_{\mathrm{th}}/p\) decides the code distance and hence the machine size.
  • Clifford logic by lattice surgery; \(T\) gates by magic-state distillation; qLDPC codes trade connectivity for far fewer qubits.

Exercises

  1. How many physical qubits does a distance-25 rotated surface code use? How many for 100 such logical qubits?
    Solution

    \(2\times625-1 = 1249\). For 100: about 125,000, before counting routing space and magic-state factories.

  2. For \(d = 3\), sketch the 9 data qubits and count the checks: how many four-qubit and how many two-qubit ones?
    Solution

    The \(3\times3\) grid of data qubits has \(2\times2 = 4\) interior faces (four-qubit checks: two \(X\), two \(Z\)) and four boundary half-faces (two-qubit checks: two \(X\), two \(Z\)). Total 8 = \(d^2-1\), as required.

  3. With \(p = 2\times10^{-3}\), \(p_{\mathrm{th}} = 10^{-2}\) and \(A = 0.1\), what distance gives \(p_L \lt 10^{-12}\)?
    Solution

    \(\Lambda = 5\). Need \((d+1)/2 > \ln(10^{11})/\ln5 = 15.7\), so \((d+1)/2 = 16\), \(d = 31\).

  4. Why does a measurement error in one cycle produce two detection events?
    Solution

    A detection event compares a check's outcome with the previous cycle. A wrong outcome in cycle \(t\) differs from cycle \(t-1\) (one event) and from cycle \(t+1\), when the correct value returns (second event). Both are on the same check, one cycle apart.

  5. A processor improves its two-qubit error from 0.5% to 0.25% with threshold 1%. How does the distance needed for \(p_L = 10^{-9}\) change (take \(A = 0.1\)), and the qubits per logical qubit?
    Solution

    \(\Lambda\) goes from 2 to 4. Need \((d+1)/2 > \ln(10^8)/\ln\Lambda\): 26.6 → \(d = 53\) at \(\Lambda=2\); 13.3 → \(d = 27\) at \(\Lambda = 4\). Qubits per logical qubit fall from about 5,600 to about 1,460.

  6. A cosmic-ray event causes errors on 30 qubits at once in a distance-7 patch for a few cycles. Why can the scaling law not protect against this, and what kinds of mitigation exist?
    Solution

    The scaling law assumes faults are independent, so long chains are exponentially rare. A burst creates a long correlated chain in one event, longer than \(d\), so the code fails regardless of \(\Lambda\). Mitigations are physical (phonon traps, gap engineering, shielding to reduce quasiparticles, Book 6) and architectural (spreading logical qubits across several chips, detecting bursts and discarding affected rounds).
